# Building a fictional store wiki

**English** · [한국어](README.ko.md)

The sources are two short, fictional notes about a store's returns policy. English versions are in [`raw-en/`](raw-en/) and the Korean originals are in [`raw/`](raw/). Both say the same thing line for line, so citations use the same line numbers.

## Try it yourself

In the README start prompt, set the project name to "Fictional store" and the docs folder to `examples/raw-en` (or `examples/raw` for Korean). For the first step, name only `returns.md` as the target. Set project history, past sessions, and memory to none, and link only the current review conversation as approval evidence.

Once the agent has created a source page and a related question page and reviewed their line citations and links, read the change proposal and decide. Then ask:

> Make a change proposal to add examples/raw-en/policy-change.md to the wiki. Also show the conditions that differ from the existing policy.

Applying the new policy's 30 days to every order would be a wrong interpretation. The 14-day/30-day split by order date and the made-to-order exception must be kept. Two policies that differ in timing and conditions should not be marked as a contradiction by default.

Question after applying:

> What is the return window for an order placed in January and for one placed in February? Give the sources too.

The expected answer is 14 days and 30 days, the exception condition, and a citation to the source for each. Take the real user decision from the current conversation and record it. The fictional approval messages in the test code exist only to exercise the tools; do not reuse them as approval evidence in a real wiki.

## What the output looks like

[`wiki-en/`](wiki-en/) is a small wiki produced from `raw-en/` by following [SCHEMA.md](../SCHEMA.md). It is stopped at the point where you would make a decision:

| Path | What it is |
|---|---|
| [`wiki-en/sources/returns-policy.md`](wiki-en/sources/returns-policy.md) | First build: summary of `returns.md` with line citations such as `^[/documents/returns.md:2]` |
| [`wiki-en/questions/return-window.md`](wiki-en/questions/return-window.md) | First build: current answer to "how long can a customer return an order?" and open points |
| [`wiki-en/index.md`](wiki-en/index.md) | Table of contents generated by `scripts/build_index.py` |
| [`wiki-en/log.md`](wiki-en/log.md) | Work history |
| [`wiki-en/reviews/2026-10-08-policy-change/`](wiki-en/reviews/2026-10-08-policy-change/) | Change proposal for `policy-change.md`, prepared with `scripts/review.py prepare` and still pending |

Inside the proposal:

- [`working/policy-change/card.json`](wiki-en/reviews/2026-10-08-policy-change/working/policy-change/card.json): the judgments (fact, scope, relationship), each with before, proposed, reason, and evidence.
- [`topics/policy-change/r0001/review.md`](wiki-en/reviews/2026-10-08-policy-change/topics/policy-change/r0001/review.md): the frozen review version with its revision hash, the judgments, and a diff of every changed page.
- `topics/policy-change/r0001/before/` and `after/`: copies of the pages before and after the change, kept as `.md.txt` so Obsidian does not treat them as real pages.
- `manifest.json`: hashes of each page and each cited source line. If a source or page changes after this point, `apply` refuses this version.

The proposal adds `sources/returns-policy-change.md`, splits the answer in `questions/return-window.md` by order date (14 days up to 2026-01-31, 30 days from 2026-02-01), and links the two source pages both ways without marking them as contested.

At this point the agent asks the user one short question, for example:

1. Update the return window from "14 days for all orders" to "14 days for orders placed up to 2026-01-31, 30 days from 2026-02-01, made-to-order exclusion unchanged", and link the two source pages without marking a conflict? (Recommended: apply / revise / defer / exclude)

There is no `decisions.jsonl` or `applied.jsonl` here. A decision has to quote a real user message from a Claude Code or Codex session file, and this example does not ship one. In your own run, `review.py decide` records your answer and `review.py apply` writes the approved pages, updates the index, and appends to the log.

Tool-generated labels (index headings, field names in `review.md`) are currently in Korean. Page content follows `wiki.language`.

To check the example yourself, from the repository root:

```bash
WIKI_CONFIG=examples/wiki-en.toml python3 -B scripts/lint.py
WIKI_CONFIG=examples/wiki-en.toml python3 -B scripts/review.py status
WIKI_CONFIG=examples/wiki-en.toml python3 -B scripts/review.py preview 2026-10-08-policy-change policy-change
```
