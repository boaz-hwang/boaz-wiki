# wiki-update

결과물은 **기간 전체의 조사 기록과 판단 보고서**, 사용자 결정 후에는 **승인된 위키 변경**이다. SCHEMA.md와 index·log를 읽는다. 특정 원문만 지정한 요청은 [wiki-ingest](../wiki-ingest/SKILL.md), 기존 위키에 대한 질문은 [wiki-query](../wiki-query/SKILL.md)의 범위다.

wiki.toml에서 위키 위치와 원천·검토자를 확인하고, 해당 위키의 SCHEMA.md를 기준으로 작업한다. 경로 예시의 docs/wiki는 설정값으로 바꾼다.

## 1. 조사 범위 확정

`review.py status`, 기존 배치 조사 기록, `applied.jsonl`과 Git 이력으로 마지막 실제 반영과 마지막 전체 검토 범위를 각각 확인한다. 부분 반영일을 전체 검토 완료일로 삼지 않는다. 불명확하면 이전 종합 검토까지 겹쳐 확인하고 보류·미검토 원천을 이어받는다. 조사 종료 시점도 고정한다.

## 2. 전체 자료 대조

[원천 탐색](references/sources.md)에 따라 wiki.toml에 등록한 문서·에이전트 기록·메모리·Git 이력을 지정 범위에서 조사한다. 결과물은 1차 근거, 대화는 결정 이유·최종 정정의 근거로 읽고 기존 관련 페이지에 대조한다. 사용자 결정과 모델 제안, 준비·실행·성과, 현재 기준과 과거 기록을 구분한다.

[조사 기록 계약](references/inventory.md)에 따라 `reviews/<batch>/inventory.json`에 원천별 접근 결과·검토 항목·분류·누락을 남긴다. 읽지 못한 자료는 검토 완료나 제외 결정으로 바꾸지 않는다. 기존 사용자 답과 승인 범위는 재사용한다.

## 3. 한 번의 판단 보고

선별한 자료를 [wiki-ingest](../wiki-ingest/SKILL.md)의 **초안 반환 방식**으로 처리하고, [wiki-review](../wiki-review/SKILL.md)로 prepare·preview 및 근거·의미·범위 검토를 수행한다. preview가 구조 검사 코드를 자동 실행한다. `python3 -B scripts/inventory.py <inventory 경로> --require-complete`를 실행한다. 정식 페이지는 아직 바꾸지 않는다.

전체 대조가 끝나면 `reviews/<batch>/overview.md`에 **조사 범위·미확인 → 추가/수정/충돌/제외 후보 → 필요한 판단 질문**을 모은다. 질문별 현재/제안 표현·근거·해석·추천 이유·적용 범위와 상세 diff를 제시한다. 질문을 자료별로 나눠 보내지 않는다. 접근 불가로 조사가 끝나지 못했다면 미완료 범위와 이를 해결할 질문을 한 번에 보고하고, 전체 검토 완료라고 하지 않는다.

완료 기준은 자료 목록의 양이 아니라 각 후보가 기존 위키와 대조됐고 사용자가 사실·해석·범위를 구별해 승인/수정/보류/제외를 결정할 수 있는가다. 자동 검사가 보장하지 못하는 근거의 적절성과 누락 가능성도 보고한다.

## 4. 결정 후 반영과 재개

사용자 결정 이후 review의 decide·apply·검증 절차를 따른다. 사용자가 명시적으로 승인분의 선반영을 요청한 경우에만 전체 검토 전 부분 반영한다. 그때도 남은 조사 범위는 유지한다.

조사 완료는 inventory, 실제 반영은 applied.jsonl로 구분한다. 부분 승인이나 보류가 있어도 전체 조사가 끝났을 수 있고, 일부를 반영했어도 조사는 미완료일 수 있다. 반영 내역·검사 결과·남은 판단을 보고하고 다음 실행은 두 기록을 함께 읽는다.
