# Clippings 원천 처리

SCHEMA.md의 외부 원천이다. 단일 파일 외에 폴더 또는 미처리 전체 요청도 받는다.

1. `python3 -B scripts/clippings_todo.py --all`로 목록을 읽고 기존 검토 상태와 대조한다. 정상 접근한 빈 폴더만 0건이다. 접근 오류는 미확인으로 보고하며 sweep 완료를 기록하지 않는다. 지정 범위 전체를 검토하고 임의의 10건 제한을 두지 않는다.
2. frontmatter의 제목·원 URL·저자·발행일과 본문의 하이라이트·메모를 읽는다. 도메인 관련성과 기존 지식에 미치는 영향을 판단한다. 외부 주장을 사용자 주장으로 바꾸지 않는다.
3. `sources/clip-<slug>.md`에 요약·핵심 주장과 줄 인용·우리 맥락에서 바뀌는 것·연결을 둔다. 핵심 주장을 빠짐없이 선별하되 개수를 목표로 하지 않는다. sources에는 `/Clippings/<상대경로>.md`와 원 URL·저자·발행일을, tags에는 clipping·external을 남긴다. 인용은 로컬 사본의 줄 범위다. 하이라이트가 없으면 위키 맥락과의 연결이 에이전트 해석임을 밝힌다. 클리핑 한 건만으로 entity를 만들지 않고 verified는 비운다.
4. 나머지 합성과 검토는 ingest와 review의 공통 절차를 사용한다. 제외 후보도 이유와 함께 묶어 질문한다. 사용자 제외 결정 후에만 `log.md`에 `## [날짜] clip-skip | <상대경로> | 이유`와 승인 근거를 기록한다. 이미 만든 ingest 검토 버전에는 rejected도 기록한다.
5. 반영·제외가 끝나면 `## [날짜] clip-sweep | N건 처리 · M건 건너뜀 · K건 검토 대기`와 대상·결정 근거를 기록한다. 정상 조사 결과 미처리가 없으면 0건 확인을 기록할 수 있다. 초안만 준비한 경우 완료 sweep으로 기록하지 않는다. 처리 수는 정식 sources, 제외 수는 사용자 결정, 대기 수는 실제 대기 목록에 대조한다.

자동 검사는 접근 가능성·파일/인용·실제 반영 여부를 확인한다. 사람은 외부 주장의 채택·제외와 위키 맥락에 연결하는 해석을 판단한다. 조사 기록은 처리 장부를 대체하지 않는다.
