# wiki-ingest

입력은 원문 한 건 또는 사용자가 지정한 묶음이다. 결과는 근거·관계·적용 범위가 있는 위키 변경안이다. SCHEMA.md와 index를 읽는다. 기간 전체의 최신화는 [wiki-update](../wiki-update/SKILL.md)가 조사와 질문 묶음을 맡는다.

wiki.toml에서 위키 위치와 원천·검토자를 확인하고, 해당 위키의 SCHEMA.md를 기준으로 작업한다. 경로 예시의 docs/wiki는 설정값으로 바꾼다.

## 1. 원천과 기존 지식 대조

원문을 줄 번호로 읽고 이미 반영됐거나 검토 대기 중인지 sources와 `review.py status`에서 확인한다. 문서 원본이 있으면 렌더 사본보다 우선한다. 세션은 SCHEMA.md에 따라 같은 주제의 결정·이유를 묶으며 결과 문서를 중복 요약하지 않는다. 클리핑 파일·폴더·미처리 묶음은 [클리핑 처리](references/clippings.md)를 적용한다.

기존 관련 페이지와 비교해 추가·보강·축소·반박·대체를 구분한다. 파일 이동은 같은 원문인지 확인한다. 원문을 고치거나 모델 제안을 사용자 결정으로 취급하지 않는다.

## 2. 연결된 변경안 작성

초안 배치·카드 형식은 [공통 검토 계약](../wiki-review/references/workflow.md)을 따른다. 필요한 변경만 작성한다.

- 일반 문서는 source에 요약·핵심 사실과 줄 인용·이 원문이 바꾸는 것·연결을 둔다. 세션과 연구의 묶음 기준은 SCHEMA를 따른다.
- concept는 여러 소스에서 쓰이는 개념을, entity는 여러 소스에 등장하거나 원문의 중심인 대상을 추가한다. 미반영 원문은 백틱 경로로 남기고 존재하지 않는 페이지에 링크하지 않는다.
- 관련 overview/question과 양방향 연결 및 본문 배치 문장을 만든다. 앵커가 없으면 근거와 열린 질문을 담은 question을 제안한다. 페이지 개수로 합성의 품질을 판정하지 않는다.
- 주장 차이는 시점·대상·적용 조건을 먼저 비교한다. 양립 불가능하면 contested와 양쪽 근거를, 대체라면 supersedes/deprecated 이력을 보존한다.

## 3. 검토에 인계

**update에서 호출됐으면 초안·근거·판단 후보만 반환한다.** 별도 질문이나 apply를 하지 않는다. **단독 요청이면 지정된 묶음 전체를 준비한 뒤 [wiki-review](../wiki-review/SKILL.md)에 넘겨 검토·사용자 결정·반영까지 진행한다.**

전달 전 근거가 문장을 실제로 지지하는지, 계획과 성과를 혼동하지 않는지, 합성 범위가 적절한지 확인한다. review의 preview 결과와 미확인 근거·미연결 원문을 함께 보고한다. 초안 수를 반영 수로 보고하지 않는다.
